# port/sim/sim/sim-modstate.frozen.txt — ticket #28.
#
# EVERY mutable file-scope `static` in the sim's translation units, with what
# a snapshot does about it. SCOPE (widened by ticket #29): the M2 gate's TU
# list PLUS sim_snapshot.c PLUS the LIVE-AI TUs (port/sim/ai.c and
# port/sim/sim/sim_ai_live.c). The live-AI pair is not on the gate's list and
# so was invisible to #28 — but the FOH binary that plays a real match links
# both, and a resumed CPU match that lost their state resumes into a different
# opponent. ai.c contributes no row: its only mutable file-scope object is the
# non-static diagnostic counter array ml_ai_cov (ai.h:82).
#
# SCOPE widened AGAIN by ticket #30, one step further out and for the same
# reason: PLUS the TARGET TUs (port/sim/target/target_play.c and
# port/sim/target/custom_stage.c), which the FOH binary links and the gate's
# list does not carry. Neither contributes a row — MEASURED: neither has a
# mutable file-scope static at all.
#
# AND A HOLE THIS FILE CANNOT COVER, stated rather than left to be discovered.
# The target plane itself is `MlTargets TP` (port/sim/target/target_play.h) —
# a file-scope NON-STATIC global, so the derivation below, which greps
# `^static`, is structurally incapable of seeing a field added to it. That
# guard lives where the struct does: target_play.c carries a _Static_assert
# over sizeof(MlTargets) against its PERSISTED and DERIVED row lists plus its
# named alignment holes, so an unclassified member does not compile. The
# snapshot row that carries the persisted half is `mod:targets`.
#
# This is the module-state twin of the
# _Static_assert in sim_snapshot.c: that assertion makes adding a member to
# GameState a build failure, and this file makes adding a module static a
# CHECK failure (port/sim/check-sim-snapshot.sh leg [2] re-derives the list
# from the sources with the exact command below and diffs it against this).
#
# Why both are needed: GameState is where the match lives, but it is not all
# of it. The port is structure-parallel, so where upstream keeps state in
# module scope — a physics.js module `let`, a move object's own property,
# howler's page-global counter — so does the port. Those bytes are sim state
# in every sense that matters to a resume, and nothing about their type
# announces it.
#
# CLASSES
#   persisted     carried in the snapshot payload; the sim_snapshot.c module
#                 row that carries it is named.
#   reconstructed rebuilt from its source by boot code BEFORE ss_load runs;
#                 the rebuilder is named. Copying it would at best be
#                 redundant and at worst (a pointer) a trap.
#   transient     holds nothing across a frame boundary — it is rebuilt or
#                 reset inside the frame that uses it. The reset site is
#                 named. A snapshot is taken at a frame boundary
#                 (oracle/CHECKSUM.md §5), which is what makes this class
#                 safe rather than merely convenient.
#
# TO REGENERATE THE LEFT-HAND COLUMNS (the check runs exactly this):
#   bash port/sim/check-sim-snapshot.sh   # leg [2] prints the derived list
#
# A NEW ROW IS A DECISION, not a formality. "transient" is the class that can
# be wrong quietly, so it is the one that has to name its reset site.
#
# format: <path> <symbol> <class> — <reason>
